# 年度日历补打卡 · 计划时长 · 周月年小时统计 — 设计规格

**日期：** 2026-08-12  
**状态：** 待实现（设计已确认）  
**范围：** 手机年度日详情位置修复；年度日历补打卡（切换完成 + 改实际时长）；可选计划时长；今日时间轴；周/月/年小时统计（柱/雷达/饼可切换）+ 入图移出/合并；习惯打卡次数独立统计  
**非目标：** 重写为完整日历时间块系统（开始+结束双字段）；强制所有计划必须有时长；改动 Focus Bay / FishTime / AI 速记核心协议（仅复用其时间轴视觉思路）

---

## 1. 背景与目标

### 1.1 现状

- 年度日历日详情（`CalendarSection.vue`）只读展示任务，不能从这里切换完成状态。
- 手机端日详情弹层 `top` 仍锚定点击格子，整体偏下。
- `PlanRecord` / `plans` 表无时长字段；AI 速记预览里的结束时间/时长提交后不落库。
- 打卡 `checks` 仅有 `done`，无「实际做了多久」。
- 周/月视图只做完成率，不做小时投入；年视图主要是热力完成度。

### 1.2 目标

1. 手机年度日详情弹层上移，更靠视口中上部。
2. 日详情内：手机长按 / 电脑右键 → 切换完成状态，并可设置/修改实际时长（补打卡）。
3. 新建/编辑计划支持**可选**时长（快捷档 + 自定义分钟）；无时长 = 纯提醒。
4. 今日区域常驻时间轴：有时长画条，无时长打点。
5. 周 / 月 / 年：以小时汇总展示「花了多少小时在什么上」；图表默认柱状，可切换柱状 / 雷达 / 饼图；用户可移出某项或合并两项；习惯打卡次数单独统计。

### 1.3 已确认决策

| 议题 | 决定 |
|------|------|
| 时长模型 | 计划时长 + 实际时长（方案 B / 实现取轻量方案 A） |
| 桌面补打卡手势 | 右键；手机长按 |
| 计划时长是否必填 | **否**；无时长不进小时统计 |
| 完成时实际时长默认 | 有计划时长则默认 = 计划时长；可改 |
| 汇总单位 | 小时（展示可用 1 位小数） |
| 图表 | 默认柱状；可切换柱状 / 雷达 / 饼图 |
| 入图控制 | 可移出；可合并两项 |
| 习惯 | 多数无时长；另统计打卡次数 |

## 2. 数据模型

### 2.1 `plans.duration_minutes`

- 类型：可空正整数（分钟）。
- `NULL` = 纯提醒，不参与小时统计（除非用户在某次打卡上单独写入实际时长——见 2.2 可选增强；**本期默认**：无计划时长则完成也不自动产生实际时长，不进小时图）。
- 新建/编辑 UI：快捷 15 / 30 / 60 / 120 + 自定义分钟 +「不设时长」。

### 2.2 `checks.actual_minutes`

- 类型：可空正整数（分钟）。
- 写入规则：
  - 切换为 **完成** 且计划有 `duration_minutes` 且当前 `actual_minutes` 为空 → 写入计划时长。
  - 切换为 **未完成** → 清空 `actual_minutes`。
  - 用户在补打卡菜单中可显式设置/修改 `actual_minutes`（仅对已完成或即将完成的项有意义；实现上允许在「设为完成」流程里一并填写）。
- 小时统计取值（单日单计划）：
  1. 若 `done` 且 `actual_minutes` 有值 → 用实际；
  2. 否则若 `done` 且计划有 `duration_minutes` → 用计划时长（视为默认实际）；
  3. 否则 → 不计小时。

### 2.3 入图偏好（移出 / 合并）

- 新表或 JSON 用户偏好（推荐独立小表，便于查询）：
  - `duration_chart_prefs`（示意）：`user_id`, `scope`（`week`|`month`|`year`）, `scope_key`（如 `2026-W33` / `2026-08` / `2026`）, `hidden_plan_ids` JSON, `merges` JSON（`[{ "label": "学习", "planIds": [1,2] }]`）
- 移出/合并**只影响图表与小时排行展示**，不删除计划、不改打卡。
- 偏好按用户持久化，换设备可用。

### 2.4 迁移

- 新 migration：`plans.duration_minutes NULL`；`checks.actual_minutes NULL`；入图表（或 prefs 行）。
- 旧数据：时长全空；行为与现在一致，小时图在无数据时显示空态。

### 2.5 API

- Plans create/update/response：增加可选 `durationMinutes`。
- Checks upsert/batch/response：增加可选 `actualMinutes`；toggle/upsert 服务端应用 2.2 默认规则（客户端也可乐观写入，服务端为准）。
- 新增或扩展：读取/保存 `duration_chart_prefs`（按 scope）。
- 可选聚合端点（非必须）：前端也可本地用 plans+checks 算；若数据量大再考虑服务端聚合。本期以前端聚合为主。

## 3. 年度日历

### 3.1 手机日详情位置

- 覆盖移动端样式：弹层垂直位置改为视口中上部（例如 `top: max(12px, 12vh)` 或固定偏上的 clamp），不再紧贴被点格子下方导致「沉底」。
- 桌面锚定点击位置的逻辑可保留，但需保证不溢出视口。

### 3.2 补打卡交互

- 日详情任务行：
  - **手机**：长按（约 500ms）打开操作菜单；
  - **电脑**：右键打开同一菜单。
- 菜单项：
  1. **切换完成状态**（完成 ↔ 未完成）；
  2. **设置/修改时长**（分钟；有计划时长时预填默认值）——对无计划时长的提醒：允许用户可选填实际分钟（若填了且完成，则进入小时统计）；不强制。
- 底层调用现有 checks upsert/toggle，带上 `actualMinutes`。

### 3.3 非目标（本期）

- 不在热力格子上直接长按改状态（必须先进入日详情）。
- DayReviewOverlay 艺术页不强制同步做补打卡（可选后续）。

## 4. 今日时间轴与计划编辑

### 4.1 时间轴

- 位置：Day / 今日区域，列表旁或列表上方；**列计划时与列完后都可见**。
- 视觉：复用 AI 速记 Gantt/数轴思路（`IntakeGanttChart` / `scheduleViz` 的时间映射），但数据源改为当日可见的 `PlanRecord`。
- 有 `durationMinutes`：从 `time` 起绘制时长条。
- 无时长：时刻点标记。
- 已完成可用样式区分（透明度/描边），不挡住补打卡入口（补打卡主入口仍在年日历日详情；今日原有单击切换完成可保留）。

### 4.2 计划表单

- 增加可选时长控件：快捷档 + 自定义 + 不设。
- AI 速记提交计划时：若草稿能解析出时长/结束时刻，写入 `durationMinutes`；解析不到则保持空。

## 5. 周 / 月 / 年小时与习惯次数

### 5.1 小时排行（主）

- 按「展示项」汇总小时：单项 = 一个 plan，或合并组。
- 展示「名称 — X.X 小时」列表/排行。

### 5.2 图表（辅，可切换）

- 默认：**柱状图**。
- 可切换：**柱状 / 雷达 / 饼图**。
- 数据与排行同一口径；雷达在类别过少（<3）时可降级提示或禁用并回退柱状。

### 5.3 入图控制

- **移出**：该项不出现在排行与图中；提供「已隐藏」列表一键恢复。
- **合并**：选择两项（或多项，本期先支持两项）合成自定义标签；小时相加；可拆分。
- 作用于当前 scope（本周/本月/本年）；切换 scope 用对应 prefs。

### 5.4 习惯打卡次数

- 独立模块：列出习惯名 + 周期内完成次数（或完成天数）。
- 不进入小时图（除非该习惯设置了时长且产生了有效小时——若有时长则**可以**同时出现在小时统计与次数统计；无时长只出现在次数）。

### 5.5 空态

- 周期内无任何有效小时：说明「完成且带时长的事项才会计入」；仍可显示习惯次数（若有）。

## 6. 跨端

- Web / Electron / Android 共用同一 Vue 实现；手势按指针类型区分（粗指针长按，精细指针右键）。
- 无单独原生日历 UI。

---

## 7. 测试与验收

1. 手机年日历点某日：弹层明显偏上，不沉底。
2. 日详情：长按/右键可切换完成；完成有计划时长时实际默认带出；可改分钟；再取消完成则清空实际。
3. 新建计划可不填时长；填快捷档后今日时间轴出现条；仅提醒项为点。
4. 周/月/年：小时列表 + 默认柱状；可切雷达/饼；移出与合并即时反映且刷新后仍在。
5. 习惯无时长：只在次数区增加，不进小时图。
6. 旧数据无时长：行为不回退；小时图空态可接受。

## 9. 开放细节（实现时可微调，不挡开工）

- 合并是否支持两项以上：本期 UI 先两项，数据结构预留数组。

- 雷达图最少类目数：建议 ≥3，否则禁用该项。
